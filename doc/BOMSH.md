# wolfSSL OmniBOR / Bomsh Integration

wolfSSL supports generating an OmniBOR artifact dependency graph using the
[Bomsh](https://github.com/omnibor/bomsh) project.  OmniBOR provides
cryptographic traceability from every binary artifact back to the exact set
of source files that produced it, complementing the component-level SBOM
generated by `make sbom`.

## Quick Start

```sh
./configure
make
make bomsh
```

This requires `bomtrace3` and `bomsh_create_bom.py` in `PATH`.  Both are
detected by `configure`; `make bomsh` fails with a clear error message if
either is missing.

## Prerequisites

| Tool | Where to get it |
|---|---|
| `bomtrace3` | Build from source: [omnibor/bomsh](https://github.com/omnibor/bomsh) |
| `bomsh_create_bom.py` | `scripts/` directory of the bomsh repo, placed in `PATH` |
| `bomsh_sbom.py` | Same; optional, needed for SPDX enrichment only |

Building bomtrace3:

```sh
git clone https://github.com/omnibor/bomsh
git clone https://github.com/strace/strace strace3
cd strace3
patch -p1 < ../bomsh/.devcontainer/patches/bomtrace3.patch
cp ../bomsh/.devcontainer/src/*.[hc] src/
./bootstrap && ./configure && make
cp src/strace ~/.local/bin/bomtrace3
```

## What `make bomsh` Does

1. Writes a build-local `_bomsh.conf` redirecting the raw logfile out of
   `/tmp/` to the build directory (avoids collisions between concurrent
   builds).
2. Runs `make clean` to ensure a full rebuild.
3. Runs `bomtrace3 -c _bomsh.conf make` — rebuilds wolfSSL under strace
   tracing, recording every compiler invocation with its input and output
   files.
4. Runs `bomsh_create_bom.py` to process the raw logfile and produce the
   OmniBOR artifact graph in `omnibor/`.
5. If `bomsh_sbom.py` is available **and** `wolfssl-<version>.spdx.json`
   exists (from `make sbom`), annotates that SPDX document with OmniBOR
   `ExternalRef` identifiers, producing
   `omnibor.wolfssl-<version>.spdx.json`.

## Output Files

| Path | Description |
|---|---|
| `omnibor/objects/` | OmniBOR artifact objects (SHA-1 dependency graph) |
| `omnibor/metadata/bomsh/` | Bomsh metadata for the build |
| `omnibor.wolfssl-<ver>.spdx.json` | SPDX 2.3 JSON enriched with OmniBOR `ExternalRef` (optional) |

## Combined SBOM + OmniBOR Workflow

For full CRA coverage — component inventory plus build traceability:

```sh
./configure
make
make sbom    # produces wolfssl-<ver>.spdx.json
make bomsh   # produces omnibor/ and omnibor.wolfssl-<ver>.spdx.json
```

## Installing

```sh
make install-bomsh    # installs omnibor/ and enriched SPDX to $(datadir)/doc/wolfssl/
make uninstall-bomsh  # removes installed files
```

The generated files are removed by `make clean`.

## Implementation Notes

`make bomsh` runs a full clean rebuild under bomtrace3 on every invocation.
This is necessary because bomtrace3 uses strace to intercept syscalls live
during compilation — it cannot post-process an already-built tree.  The
~20% runtime overhead of bomtrace3 means the rebuild takes roughly 1.2×
the normal build time.

The raw logfile (`bomsh_raw_logfile.sha1`) and conf file (`_bomsh.conf`)
are written to the build directory and removed by `make clean`.  The
`omnibor/` tree is also removed by `make clean`.
